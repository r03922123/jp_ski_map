# UX panel, 2026-11-23: four reviewers, phone + desktop

**Method.** Four agent reviewers, each with one lens, used `main` at `ea074e1` on a dev server (`next dev`), each
driving its own Playwright browser:
- mobile researcher: first-time visitor, WebKit iPhone 15 emulation (393×659, touch), five tasks;
- desktop researcher: trip planner used to Google Maps, Chromium 1440×900 (also 1280×720, 1920×1080);
- UI engineer: layout and craft at iPhone SE, iPhone 15 (WebKit), 768×1024 and 1440×900 (Chromium), light and dark;
- accessibility and performance: keyboard, aria snapshots, contrast from computed colours, request counts, timings.

Each finding was reproduced by its reviewer; each fixed one was reproduced again by its fix agent as a failing test
before the fix. It is off-season (shuttles start 2026-12-13), so bus tasks used December dates. Timings come from the
dev build on a loaded Mac: compare them with each other only.

Not covered: real iPhone, VoiceOver, the iOS keyboard, long-press (WebKit emulation can't hold a touch), real GPS,
Android, a production build.

**What held up:** forgiving search ("hakuba eki", "白馬駅", "hapo one"); a picked bus journey answers "where do I
board" at a glance; every forced API failure shows a plain in-place message; no horizontal scroll from 375 to 1440 px;
reduced motion is respected; zero console errors.

Codes: M = mobile, D = desktop, U = UI engineer, A = accessibility/performance. Known = already in the
[2026-11-03 review](2026-11-03-ux-review.md).
